Sub-step 2.1

Build the mean-prediction baseline

Fit a DummyRegressor that predicts the training mean for every row. This is your minimum standard, not a model to deploy.

HintA useful model must beat the baseline on the metrics that matter to this problem.

Pause and reflect

If the baseline has a negative R² score on test data, is that necessarily an error? Explain.

Sample code
from sklearn.dummy import DummyRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
baseline = DummyRegressor(strategy="mean").fit(X_train, y_train)
baseline_pred = baseline.predict(X_test)
print("MAE:", mean_absolute_error(y_test, baseline_pred))
print("RMSE:", mean_squared_error(y_test, baseline_pred) ** 0.5)
print("R²:", r2_score(y_test, baseline_pred))
You have a meaningful minimum standard to beat.
Sub-step 2.2

Choose how to read performance

Use MAE, RMSE and R² together when reporting results. Decide which error type would be most costly for bike operations.

HintMAE is a typical absolute miss. RMSE gives extra weight to large misses. R² compares against predicting the mean; it is not accuracy.

Pause and reflect

Give one example where two models have similar MAE but one has a much worse RMSE.

Sample code
def report_metrics(actual, predicted):
    print(f"MAE:  {mean_absolute_error(actual, predicted):.2f}")
    print(f"RMSE: {mean_squared_error(actual, predicted) ** 0.5:.2f}")
    print(f"R²:   {r2_score(actual, predicted):.3f}")
You can report performance without reducing it to one score.
Sub-step 3.1

Fit contrasting models

Train linear, regularised linear and tree-based approaches. Start with an initial test comparison to understand their behaviour—but do not select a final winner yet.

HintLinear Regression is an interpretable benchmark; trees and ensembles can represent more complex relationships.

Pause and reflect

Which model is easiest to explain to a non-technical stakeholder? Which may capture non-linear patterns better?

Sample code
from sklearn.linear_model import LinearRegression, Ridge
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor, GradientBoostingRegressor
models = {"Linear": LinearRegression(), "Ridge": Ridge(alpha=1.0),
          "Tree": DecisionTreeRegressor(random_state=42),
          "Forest": RandomForestRegressor(n_estimators=150, random_state=42, n_jobs=-1),
          "Boosting": GradientBoostingRegressor(random_state=42)}
You have tested models that make different assumptions.
Sub-step 3.2

Make an initial comparison

Fit each candidate and present a sorted results table. Treat the ranking as a learning checkpoint, not final model selection.

HintOne fortunate or unfortunate split can change the rankings. The next theme reduces that risk.

Pause and reflect

Pick the apparent winner. What evidence is still missing before you would recommend it?

Sample code
rows = []
for name, model in models.items():
    model.fit(X_train, y_train)
    pred = model.predict(X_test)
    rows.append([name, mean_absolute_error(y_test, pred),
                 mean_squared_error(y_test, pred) ** 0.5, r2_score(y_test, pred)])
initial_results = pd.DataFrame(rows, columns=["model", "MAE", "RMSE", "R2"])
print(initial_results.sort_values("RMSE"))
You have an initial comparison and a reason not to over-trust it.
Sub-step 4.1

Cross-validate every candidate

Use the same five shuffled folds of the training data for every model. Compare mean RMSE and its spread across folds.

HintScikit-learn returns error scores as negative values because its scoring convention treats bigger as better. Reverse the sign before reporting them.

Pause and reflect

Complete: “Using the same folds is fair because ___.”

Sample code
from sklearn.model_selection import KFold, cross_validate
cv = KFold(n_splits=5, shuffle=True, random_state=42)
scoring = {"mae":"neg_mean_absolute_error", "rmse":"neg_root_mean_squared_error", "r2":"r2"}
cv_rows = []
for name, model in models.items():
    scores = cross_validate(model, X_train, y_train, cv=cv, scoring=scoring, n_jobs=-1)
    cv_rows.append([name, -scores["test_rmse"].mean(), scores["test_rmse"].std()])
cv_results = pd.DataFrame(cv_rows, columns=["model", "mean_RMSE", "RMSE_sd"])
You can now compare average performance and consistency.
Sub-step 4.2

Tune one promising candidate

Select a candidate using cross-validation evidence, then search a small, purposeful Random Forest hyperparameter grid on training data only.

HintParameters are learned during fitting. Hyperparameters—such as tree depth—are set before fitting and chosen through validation.

Pause and reflect

Count the grid combinations. What trade-off would you make if the search took too long?

Sample code
from sklearn.model_selection import GridSearchCV
grid = {"n_estimators":[10,100], "max_depth":[None,5,10],
        "min_samples_split":[2,5], "max_features":["sqrt",1.0]}
search = GridSearchCV(RandomForestRegressor(random_state=42, n_jobs=-1),
    grid, scoring="neg_root_mean_squared_error", cv=cv, n_jobs=-1, refit=True)
search.fit(X_train, y_train)
print(search.best_params_, -search.best_score_)
You have tuned without spending the test set.

Sub-step 5.2

Inspect errors and make a responsible decision

Review the largest residuals and compare training performance with test performance. State how the model should be monitored if adopted.

HintSummary metrics can hide costly patterns. A large training-to-test gap may suggest overfitting; a small gap is encouraging but not a guarantee.

Pause and reflect

Name one condition shared by large errors, one operational risk, and one metric you would monitor each month.

Sample code
import numpy as np
residuals = y_test - final_pred
error_review = X_test.copy()
error_review["actual"] = y_test
error_review["predicted"] = final_pred
error_review["residual"] = residuals
error_review["absolute_error"] = np.abs(residuals)
print(error_review.sort_values("absolute_error", ascending=False).head(10))
